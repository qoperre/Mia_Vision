# Qwen3-VL 실시간 터치 게임 검증 보고서

검증일: 2026-07-14 (Asia/Seoul)

## 최종 판정

두 목표를 모두 초과 달성했습니다.

| 게임 | 목표 | 최종 반복 검증 |
|---|---|---|
| 게임 1 | 오류 0회, 10초 미만 | 5/5 시드 통과, 오류 합계 0회, 7.018~7.197초 |
| 게임 2 | 장애물 20개 이상 | 3/3 시드 통과, 모든 실행에서 21점 |

`tests/game_results/latest.json`의 마지막 통합 실행도 `all_passed: true`입니다.

## 입력과 상호작용 경로

제어기는 게임의 DOM 좌표를 읽지 않습니다.

1. Chrome이 게임 화면을 PNG로 렌더링합니다.
2. Qwen3-VL과 OpenCV가 해당 픽셀을 분석합니다.
3. 좌표는 Chrome DevTools Protocol의 실제 `touchStart`/`touchEnd` 이벤트로 입력됩니다.
4. `game1State`와 `game2State`는 게임 종료 후 결과를 판정하고 게임오버를 심판하는 데만 사용됩니다.

Windows의 200% DPI 환경에서도 브라우저 CSS 좌표와 device scale 1을 사용하므로 OS 화면 배율에 따른 터치 오차가 발생하지 않습니다.

## 게임 1

### 최적화된 제어

- 최초 화면을 2배 업스케일하여 Qwen3-VL이 숫자 1~4와 정규화 중심 좌표를 한 번에 반환합니다.
- OpenCV가 흰 원 네 개의 정확한 중심을 찾습니다.
- Qwen 좌표와 원 중심을 4! 전역 최소거리로 일대일 배정하여 좌표 오차를 제거합니다.
- 이후 각 실제 터치 뒤 화면을 다시 받아, 움직이지 않은 세 원과 새로 생긴 원의 차이를 추적합니다.
- 새 원은 게임 규칙에 따라 직전 숫자+4로 등록됩니다.
- 50회 터치와 최초 Qwen 호출 시간이 모두 게임 타이머에 포함됩니다.

낮은 해상도에서 Qwen 좌표를 그대로 터치하면 좌표 오차가 커질 수 있었습니다. 이미지 토큰을 1024로 고정하고 전역 원 중심 스냅을 적용한 후 모든 시드에서 오류 0을 재현했습니다.

## 게임 2

### 최적화된 제어

- 물리는 멈추지 않으며 실제 시간으로 계속 진행됩니다.
- OpenCV 피드백은 약 7 FPS로 노란 새와 청록색 파이프의 빈 공간을 추적합니다.
- 새의 고유한 주황색 부리·날개를 기준점으로 사용해 노란 `NEXT` 글자와 새를 혼동하지 않습니다.
- 파이프의 청록색 위·아래 부분을 직접 분리하여 빈 공간 중심을 계산합니다.
- 각 새 장애물마다 Qwen3-VL을 비동기로 호출합니다. `bird_y/gap_y`만 반환하는 작은 JSON 스키마로 지연과 오인식을 줄였습니다.
- Qwen 결과가 CV와 합리적인 범위에서 일치하면 다음 비행 목표에 혼합하고, 큰 불일치는 안전을 위해 거부합니다.
- 모든 플랩은 실제 화면 터치 이벤트입니다.

### 반복 결과

|---:|---:|---:|---:|---:|---:|---:|
| 42 | 21 | 54.821초 | 56 | 7.02 | 21 | 14 |
| 9999 | 21 | 54.822초 | 57 | 7.02 | 21 | 14 |
| 20260714 | 21 | 54.808초 | 55 | 7.01 | 21 | 11 |

브라우저 콘솔 오류, 화면 검출 실패 및 OOM은 최종 실행에서 모두 0회였습니다.

서버 로그의 `making room for prompt cache entry` 메시지는 서로 다른 스크린샷 캐시를 교체하는 정상 동작이며 CUDA 메모리 오류가 아닙니다. 실제 `CUDA error`, `out of memory`, `OOM`, 할당 실패는 0건입니다.

## 수정 반복 기록

1. 게임 1 최초 구성도 8.336초·오류 0으로 목표를 통과했지만 여유가 작았습니다. 이미지 토큰을 1024로 고정해 Qwen 인식을 약 2.21초에서 약 0.98~1.20초로 줄였습니다.
2. 게임 2 최초 검출기는 브라우저 축소 시 새 몸체가 두 색상 컴포넌트로 나뉘어 새를 놓쳤습니다. 형태 결합과 주황색 기준점을 추가했습니다.
3. 파이프가 새에 가까워질 때 노란 점선 대신 `NEXT` 글자를 갭으로 오인해 충돌했습니다. 청록색 파이프 상·하단 사이의 실제 빈 영역을 계산하도록 변경했습니다.
4. 복잡한 Qwen 좌표+행동 스키마는 갭 오인식이 있었습니다. `bird_y/gap_y` 두 필드로 축소하자 동일 테스트 프레임에서 갭 중심을 정확하게 반환했고 응답도 빨라졌습니다.
5. Qwen 단독 프레임 제어는 응답 주기가 물리 피드백보다 느리므로, 장애물별 비동기 의미 인식과 고주기 픽셀 추적을 결합했습니다.
